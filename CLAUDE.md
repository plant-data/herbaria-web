# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`herbaria-web` is the Floritaly digital herbarium portal: a React 19 + Vite SPA for searching, mapping, and visualizing botanical specimen collections. It is a pure frontend that talks to a separate specimens API over POST; there is no backend in this repo.

## Commands

Package manager is **pnpm**.

- `pnpm dev` — dev server on port 3000 (`pnpm mobile` exposes it on the LAN via `--host`)
- `pnpm build` — `vite build` then copies `.htaccess` into `dist/` (needed for SPA rewrites on Apache)
- `pnpm serve` — preview a production build
- `pnpm test` — run Vitest once (jsdom env, globals enabled). Run a single file with `pnpm test <path>` or a single test with `pnpm test -t "<name>"`. Note: there are currently no test files in the repo.
- `pnpm lint` — ESLint (`@tanstack/eslint-config`)
- `pnpm format` — Prettier write; `pnpm check` runs Prettier + `eslint --fix`

Prettier enforces no semicolons, single quotes, `printWidth: 120`, trailing commas. TypeScript is strict with `noUnusedLocals`/`noUnusedParameters`, so unused imports/vars will fail the build.

## Environment

Config is read from Vite env vars in [src/config.ts](src/config.ts). `.env` is gitignored (no `.env.example` is tracked). Required vars:

- `VITE_API_BASE_URL` — base URL of the online specimens API (must end with `/`)
- `VITE_LOCAL_API_BASE_URL` — base URL of the local plantdata-resources public API (must end with `/`); optional, defaults to `http://localhost:8000/api/v1/`. Currently only the search **filter panel** (option suggestions/counts and the year/altitude histograms) reads from here, via [src/features/search/api/local-backend.ts](src/features/search/api/local-backend.ts); results, map and graphs still use `VITE_API_BASE_URL`.
- `VITE_IMAGE_BASE_URL` — base URL for specimen images
- `VITE_ITEMS_PER_PAGE` — page size (parsed as Number)
- `VITE_BASE_PATH` — public path prefix; used for locale loading and favicon/asset hrefs
- `VITE_ENVIRONMENT` — `'development'` | `'production'` (`IS_DEV` derives from this)

The app is served under a subpath: `vite.config.js` sets `base: '/herbaria/'` and `.htaccess` sets `RewriteBase /herbaria/`. Keep these in sync if the deploy path changes.

## Architecture

### Routing — TanStack Router, file-based

Routes live in [src/routes/](src/routes) and are compiled into `src/routeTree.gen.ts` **automatically** by the `tanstackRouter` Vite plugin (`autoCodeSplitting: true`). Do not edit `routeTree.gen.ts` by hand.

- `$herbariaId` is the dynamic collection segment. The special value `all` means "search across every collection".
- `$herbariaId/(search)/` is a pathless layout group ([route.tsx](src/routes/$herbariaId/(search)/route.tsx)) rendering the shared sidebar + navbar shell, with child routes `table`, `map`, `graphs`, `images` as the result views.
- The `(search)` route's `loader` seeds the filter store: for any `herbariaId` other than `all` it locks `institutionCode` to that collection (via `setInstitutionCodeNoResetSkip`). Per-collection pages pass `lockedFilters` so "reset filters" preserves the collection scope.

### Global filter state — Zustand

[src/features/search/stores/use-filters-store.tsx](src/features/search/stores/use-filters-store.tsx) is the single source of truth for all search filters (scientific name, genus, country, locality, geometry, year range, month, institution, coordinates, etc.) plus map view state (`zoom`/`bbox`/`mapCenter`). Key conventions:

- Setters are generated by a `createSetter` factory that mimics React's `useState` (accepts a value or updater fn), optionally sorts array values, and by default resets pagination (`skip`) on change. `activeFiltersCount` is recomputed on every mutation.
- `skip`, `zoom`, `bbox`, `mapCenter`, and `activeFiltersCount` are **not** user-facing "visible" filters.
- Uses the `devtools` middleware (store name `filter-store`) — actions are named for Redux DevTools.

### Data fetching — one generic hook over one POST client

All specimen data goes through [src/features/search/api/get-occurrences.tsx](src/features/search/api/get-occurrences.tsx). The internal `useSpecimensQuery` hook reads the whole filter store, runs `prepareQueryPayload` to build the request body, and calls the single [postApiClient](src/api/post-api-client.tsx) (POST + JSON + `AbortSignal`). Public hooks — `useSpecimensData`, `useSpecimensMap`, `useSpecimensCount`, `useSpecimensGraph`, `useSpecimensPoint`, `useSpecimensCluster` — differ only by `searchType`.

`searchType` selects endpoint + query key from `SEARCH_CONFIG` in [constants.tsx](src/features/search/constants/constants.tsx). `prepareQueryPayload` strips non-filter fields (`skip`, `activeFiltersCount`), drops the year range when it equals `[MIN_YEAR, MAX_YEAR]`, and only sends map view fields (`zoom`/`bbox`/`mapCenter`) for `searchType: 'map'`. The React Query key is derived from the payload so any filter change refetches. `COMMON_QUERY_OPTIONS` sets a 24h stale/gc time and no refetch on focus/mount — treat specimen data as heavily cached.

TanStack Query is provided in [src/integrations/tanstack-query/](src/integrations/tanstack-query).

### Collections config

[src/features/search/constants/herbaria.tsx](src/features/search/constants/herbaria.tsx) (`HERBARIA_CONFIG`) is the registry of collections — id (institution code, e.g. `PI`), landing-page hero/stats/sections content (as i18n keys), images, and a per-collection `ringColor` that `__root.tsx` injects as the `--ring` CSS variable. Add a collection here to give it a landing page and theming.

### i18n

`react-i18next` + `i18next-http-backend` loads `public/locales/{en,it}/translation.json` at runtime from `${BASE_PATH}locales/...` ([src/i18n.ts](src/i18n.ts)). Languages: English and Italian, `fallbackLng: 'en'`. Most user-facing strings in config/constants are stored as translation **keys**, not literals — resolve them with `t()`.

### UI

shadcn/ui (`new-york` style, slate base) components in [src/components/ui/](src/components/ui); add new ones with the shadcn CLI (see `components.json`). Tailwind CSS v4 via `@tailwindcss/vite` (no `tailwind.config`; theme lives in [src/styles.css](src/styles.css)). Icons: `lucide-react`. Path alias `@/` → `src/`.

Maps use **Leaflet** / `react-leaflet` (+ `leaflet-draw` for drawing filter geometry). Deep-zoom specimen images use **OpenSeadragon**. Charts use **ECharts** (`echarts-for-react`). React Compiler is enabled (`babel-plugin-react-compiler` in `vite.config.js`), so avoid manual memoization unless profiling shows a need.
